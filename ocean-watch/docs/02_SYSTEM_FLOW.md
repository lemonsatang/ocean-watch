# 02_SYSTEM_FLOW.md - 시스템 및 데이터 흐름도

본 문서는 수산물 디지털 이력 기반 AI 공정가격 보증 플랫폼의 핵심 비즈니스 로직과 데이터의 라이프사이클을 정의한 흐름도이다. 안티그래비티는 API 및 서비스 로직을 구현할 때 이 순서와 제약사항을 반드시 준수해야 한다.

---

## 1. 전체 수산물 유통 파이프라인 (Main Distribution Cycle)

수산물이 포획되어 소비자에게 도달하기까지의 표준 흐름이다.

`[생산자(어부)]` ──(1차 등록)──▶ `[도매업자]` ──(2차 재판매)──▶ `[소매업자]` ──(최종 판매/QR발급)──▶ `[소비자]`

1. **생산자 등록:** 어부가 수확한 수산물의 중량과 판매가를 입력하고 수취인(도매업자)을 지정하여 거래를 등록. (`buy_price` = 0)
2. **도매업자 인수:** 지정된 도매업자가 물품 검수 후 승인(또는 수량 정정).
3. **도매업자 판매:** 도매업자가 마진을 붙여 소매업자를 지정해 새로운 판매 거래 등록.
4. **소매업자 인수 및 판매:** 소매업자가 승인 후, 최종 소비자 판매용 매대 QR 코드를 발급.
5. **소비자 스캔:** 소비자가 QR 스캔 시 1~4번의 전 과정을 역추적하여 조회.

## 2. 거래 상태 전이 및 Trace ID 계층 생성 흐름 (Trade State Flow)

하위 유통업자가 상위 유통업자의 물품을 인수할 때 발생하는 데이터 베이스 상태 전이 흐름이다.

* **상태 전이 모델:**
  * `PENDING` (인수 대기) ──▶ `APPROVED` (전량 승인) 
  * `PENDING` ──▶ `PARTIAL_APPROVED` (부분 승인/수량 정정)
  * `PENDING` ──▶ `REJECTED` (인수 거절)

* **Trace ID(유통 이력) 상속 흐름:**
  1. 도매업자(B)가 생산자(A)의 거래(Trace ID: `T-001`)를 승인(`APPROVED`).
  2. 도매업자(B)가 소매업자(C)에게 50kg을 쪼개서 분할 판매 등록.
  3. 시스템은 **새로운 Trace ID**(`T-002`)를 발급하고, `parent_trace_id` 컬럼에 `T-001`을 매핑하여 트리(Tree) 구조를 형성.

* **거절(REJECTED) 데이터 처리 흐름:**
  * 수취인이 거절 시 DB에서 해당 row를 `DELETE` 하지 않는다.
  * 상태만 `REJECTED`로 업데이트하며, 조회 쿼리(조건절 및 인덱스)를 통해 수취인의 목록에서는 즉시 숨김 처리된다. 발송자는 마이페이지에서 이를 확인하고 타 업자를 재지정할 수 있다.

## 3. AI 공정가격 실시간 판정 흐름 (AI Pricing Flow)

유통업자가 **"판매 등록"**을 수행하는 순간(API 호출 시) 발생한다.

1. **데이터 입력:** 유통업자가 판매가(`sell_price`)와 어종 코드(`fish_code`) 입력 후 등록 요청.
2. **AI 밴드 조회:** 백엔드에서 `TB_AI_FAIR_PRICE`를 조회하여 해당 어종의 당일 적정가 밴드(최소~최대) 획득.
3. **상태 판정 (백엔드 로직):**
   * 입력한 `sell_price`가 밴드 내에 존재 ──▶ `ai_fair_yn` = **'Y' (초록불)**
   * 입력한 `sell_price`가 밴드 상단 소폭 초과 ──▶ `ai_fair_yn` = **'W' (노란불/경고)**
   * 입력한 `sell_price`가 밴드 상단 대폭 초과 ──▶ `ai_fair_yn` = **'N' (빨간불/폭리)**
4. **저장:** 판정된 신호등 결과값을 `TB_DISTRIBUTION_TRACE` 테이블에 함께 `INSERT`.

## 4. 소비자 QR 스캔 및 데이터 역추적 흐름 (QR Tracking Flow)

소비자가 모바일 기기로 매장의 QR 코드를 스캔했을 때의 내부 처리 흐름이다.

1. **QR 스캔:** QR 코드에 삽입된 URL(`https://domain.com/trace/{traceId}`)로 접속.
2. **API 호출:** 프론트엔드에서 최종 단계(소매상)의 `trace_id`를 파라미터로 백엔드 조회 API 호출.
3. **재귀 추적 (DB View):**
   * 백엔드는 `VW_CONSUMER_TRACE` 뷰를 호출.
   * DB 단에서 `parent_trace_id`를 기반으로 소매업자 ──▶ 도매업자 ──▶ 생산자 순으로 재귀(Recursive) 쿼리를 실행하여 트리를 평탄화(Flatten).
4. **시세 연동:** 해당 어종의 당일 공공데이터 시세(`TB_PRICE_HISTORY`)를 추가 조회.
5. **화면 렌더링:** 타임라인 형태의 유통 이력 및 마진 흐름, AI 공정가 신호등을 소비자 화면에 즉시 표시 (목표 응답 시간: 100ms 이내).
